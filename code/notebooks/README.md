# Notebook guide

These twenty-two independent notebooks accompany *From Brains to Models* for MSc and PhD students in biomedicine, imaging and computational science. Each includes an **Open in Colab** badge, learning goals, setup instructions and two reading paths explaining the concepts and notation used in its calculations. Read the explanations beside the calculations, predict a result before changing a parameter, and use the interpretation questions to design a further test.

**Related resources:** [Paper](../../paper/main.pdf) · [Presentation guide](../../talk/resources.md)

## Running and saving

In Colab, connect to a standard CPU runtime and run the setup cell first, then run the remaining cells in order. Setup downloads a small checkout containing the shared code and figure references; the PPTX is excluded. It installs NumPy and Matplotlib if needed; 14b and 14c also install NiBabel for NIfTI input. Notebook 05b also installs and enables `ipywidgets`/`ipympl`; 14a–14c and 15 install `ipywidgets` and enable Colab widget support. No model weights, patient data, API keys or Drive mount are needed. See [Google's GitHub notebook guide](https://colab.research.google.com/github/googlecolab/colabtools/blob/main/notebooks/colab-github-demo.ipynb) for opening and saving copies.

For mouse interaction in [05b](05b_multistable_animation.ipynb), open the widget cell’s output menu (⋮) and choose **View output fullscreen** for contour clicks and 3-D rotation. Press **Esc** to return to the notebook.

Notebooks 14b and 14c read about 9.25 MB of checksum-verified normal BrainWeb data bundled under [the package data directory](../src/brainsmodels/data/brainweb/README.md). After checkout and dependency setup, no network or companion repository is required. The T1 and tissue labels are phantom source data, not patient observations or tumour targets. Input files retain BrainWeb terms and attribution. A missing or changed input raises an error; no substitute anatomy is used. See [growth provenance and checks](../../README.md#growth-lessons-and-provenance).

Use **File → Save a copy in Drive** to keep notebook edits. Files generated in the runtime are separate from that saved notebook; download any figures, GIFs or JSON records you want to retain. The runtime is temporary. Re-running setup preserves its existing checkout; to start from current repository code, disconnect and delete the runtime before reconnecting.

For local use, follow the [environment instructions](../../README.md#run-the-notebooks), choose the project's Python kernel and restart and run all cells. Each notebook finds the checkout and sets its working directory to `code/notebooks`. The [worked exercises](../solutions/README.md) can then be loaded with `%load ../solutions/<filename>.py` or copied from the embedded solution blocks.

## Using the notebooks for teaching

Read the biomedical/imaging explanation for the observable contrast and its interpretation. Use the computational path for the variables, objective and update rule. The paths describe the same calculation. Neither needs to be completed before the other.

For notebook 09's interpretation exercise, run cells individually and pause before displaying an overlay. Notebook 05b has static figures and a GIF as well as its interactive panel; browser widget support affects interaction, not the underlying descent calculation. Notebook 13's independent references run by default; its optional audit of a pinned external 3-D solver is a separate, explicitly reported step.

The [instructor discussion notes](questions_responses.md) and embedded exercises extend the conceptual notebooks. For a short session focused on the presentation, start with 10, 11 or 12, then use 08, 09 or 13 for a more detailed investigation. Use 00–07 and their lettered companions to develop the broader concepts. Each notebook identifies what its calculation measures and the observations or controls needed to investigate a biological or imaging application.

For a growth-modelling session, use **13 → 14a → 14b → 14c**: numerical verification, density-to-measurement choices, anatomical context, then generated-data inference and a withheld forecast. Each remains independently runnable. Allow time to predict each result before executing its calculation. The 2-D map in 14a is constructed; the 3-D anatomy in 14b/14c is BrainWeb. Their output units and evidence status are explained beside each result.

For prediction and decision-making, use **15**: start with the paper's expected 10,000-person table, derive PPV, then compare two actions under stipulated costs. Sliders vary prevalence, sensitivity and specificity separately from decision probability and costs. The notebook distinguishes a classifier's operating threshold from a cost-based decision threshold and includes worked exercises for both reading paths.

## Interactive growth controls

Run the interactive cell in 14a–14c to create the widgets. Model and algorithm changes take effect when you press the run button. In 14a/14b, day, threshold and image-view controls read the last computed run immediately. A pending-change message prevents a previous result from being mistaken for a new simulation. Invalid time steps are rejected explicitly.

In 14c, compare noise seeds, generating rates, early observation times, search resolution and fitting steps. Day 90 is always withheld. The static examples above the controls remain the reproducible paper reference; widgets do not overwrite them. GitHub shows those saved figures, while interactivity requires a running kernel.
